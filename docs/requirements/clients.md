# Требования: clients

Источник: [`knowledge/requirements/clients.md`](../../knowledge/requirements/clients.md)

## REQ-CLIENT-01

**Клиент заводится один раз оператором**

предложено · владелец: продукт · схема: §1, §6

Нового клиента заводит оператор. Клиент заводится в системе один раз, его данные общие для всех его заявок.

- Реализуют: ⚠ правил нет — в коде не реализовано
- ⚠ Расходятся: R-SCHEMA-CLIENT-01

## REQ-CLIENT-02

**Данные клиента обновляет проверяющий**

предложено · владелец: продукт · схема: §2, §6

Обновлять данные клиента (например, при смене паспорта) может только проверяющий. Оператор после проверки данные клиента не меняет.

- Реализуют: ⚠ правил нет — в коде не реализовано
- ⚠ Расходятся: R-APP-CLIENT-01

## REQ-CLIENT-03

**Каждая заявка проходит проверку данных клиента**

предложено · владелец: продукт · схема: §2, §6

Каждая новая заявка проходит проверку, даже если клиент уже проверялся: данные могли устареть. Проверяющий убеждается, что все нужные данные о клиенте есть и они актуальны.

- Реализуют: [R-APP-REVIEW-04](../rules/applications.md) (подкреплено кодом и тестами)

## REQ-CLIENT-04

**Обновление данных клиента возвращает его заявки на проверку**

предложено · владелец: продукт · схема: §4, §6

Обновление данных клиента сразу видно во всех его заявках. Другие его заявки, которые ещё не дошли до записи, снова уходят на проверку; заявки на этапе записи и дальше не перепроверяются.

- Реализуют: [R-APP-CLIENT-02](../rules/applications.md) (⚠ без тестов), [R-APP-CLIENT-03](../rules/applications.md) (⚠ расхождение с требованием или открытый вопрос)

## REQ-DEDUP-01

**Из двух заявок клиента по одной сфере остаётся первая дошедшая до записи**

предложено · владелец: продукт · схема: §6

Если у клиента две заявки по одной сфере, остаётся та, что первой дошла до записи: платная — в момент полной оплаты, в долг — когда прошла проверку. Социальные и платные заявки не пересекаются. Заявки по разным сферам друг на друга не влияют.

- Реализуют: [R-BILL-PROCESS-01](../rules/billing.md) (⚠ расхождение с требованием или открытый вопрос)
- ⚠ Расходятся: R-APP-DEDUP-01

## REQ-DEDUP-02

**Дубль закрывается окончательно, его счёт аннулируется**

предложено · владелец: продукт · схема: §4, §6

Вторая заявка закрывается автоматически и окончательно, без ухода в архив; вернуть её нельзя. Выставленный по ней счёт аннулируется.

- Реализуют: [R-APP-DEDUP-02](../rules/applications.md) (⚠ расхождение с требованием или открытый вопрос), [R-SCHED-RESET-01](../rules/scheduling.md) (⚠ без тестов)
- ⚠ Расходятся: R-BILL-DUPLICATE-01
