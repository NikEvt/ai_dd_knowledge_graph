# Правила: schema

Источник: [`knowledge/rules/schema.yaml`](../../knowledge/rules/schema.yaml)

## R-SCHEMA-CLIENT-01 — Клиент заводится один раз оператором, данные общие для всех заявок

`draft` · constraint

Достоверность: по требованию REQ-CLIENT-01 · ⚠ код расходится с требованием REQ-CLIENT-01 (D-23): реализовано частично: create_client не проверяет роль; у applications.clients нет уникальности (паспорт, ФИО+дата рождения), поэтому один и… — уточни у пользователя

Нового клиента заводит оператор. Клиент заводится в системе один раз, и его данные общие для всех его заявок.

- Реализация: [`services/applications/service.py::create_client`](../../services/applications/service.py#L63)
- Роли: Оператор
- ⚠ Расходится с [REQ-CLIENT-01](../requirements/clients.md#req-client-01): реализовано частично: create_client не проверяет роль; у applications.clients нет уникальности (паспорт, ФИО+дата рождения), поэтому один и тот же клиент может быть заведён дважды — и тогда дедупликация по client_id+sphere_id не сработает

## R-SCHEMA-APP-01 — Оператора заявки переназначить нельзя

`draft` · constraint

Достоверность: реализует требование REQ-ROLE-03 · ⚠ открытый вопрос D-28: Добавить ли триггер, запрещающий DELETE заявок и UPDATE operator_id? — уточни у пользователя

Оператор — создатель заявки. Переназначить оператора нельзя: на время отсутствия оператор передаёт свою учётную запись коллеге.

- Реализация: [`services/applications/service.py::create_application`](../../services/applications/service.py#L70)
- Роли: Оператор
- Реализует требования: [REQ-ROLE-03](../requirements/roles.md#req-role-03)
- Оговорка: реализовано неявно: operator_id задаётся только при создании и в коде нигде не меняется; в БД защиты нет — trg_applications_core_immutable охраняет только sphere_id и representative_id

## R-SCHEMA-LINK-01 — По ссылке нельзя изменить данные заявки

`draft` · constraint

Достоверность: реализует требование REQ-BOOK-06 · извлечено ИИ из кода, есть код, нет тестов — сверь с кодом

Через публичную ссылку можно только посмотреть свободные окна, записаться, перенести или отменить визит. Данные заявки по ссылке изменить нельзя.

- Реализация: [`services/scheduling/api.py::slots`](../../services/scheduling/api.py#L27), [`services/scheduling/api.py::book`](../../services/scheduling/api.py#L35), [`services/scheduling/api.py::cancel`](../../services/scheduling/api.py#L41)
- Роли: Клиент, Представитель клиента
- Реализует требования: [REQ-BOOK-06](../requirements/scheduling.md#req-book-06)

## R-SCHEMA-FINE-01 — О просрочке представителю сообщает оператор по почте

`draft` · obligation

Достоверность: по требованию REQ-FINE-04 · ⚠ код расходится с требованием REQ-FINE-04: реализовано частично: система только пишет в чат «Срыв срока возврата книги»; задачи или напоминания оператору нет, факт уведомления не фик… — уточни у пользователя

Когда система отметила срыв срока возврата, оператор вручную сообщает о просрочке представителю по почте вне системы.

- Реализация: [`services/scheduling/jobs.py::flag_overdue`](../../services/scheduling/jobs.py#L10), [`services/chat/consumers.py::_handler`](../../services/chat/consumers.py#L23)
- Роли: Оператор
- ⚠ Расходится с [REQ-FINE-04](../requirements/loans.md#req-fine-04): реализовано частично: система только пишет в чат «Срыв срока возврата книги»; задачи или напоминания оператору нет, факт уведомления не фиксируется

## R-SCHEMA-SPHERE-01 — Название сферы уникально

`draft` · constraint

Достоверность: поведение кода без бизнес-требования · ⚠ открытый вопрос D-27: Подтверждаете ли, что название сферы глобально уникально (а не в пределах площадки)? — уточни у пользователя
