**Что Ruflo запомнил** (5 записей, по одной на задачу; выгрузка — `library-eval/results/ruflo_memory_smb1/`). Каждая запись описывает найденную ловушку — то есть ровно те неочевидные связи, ради которых строилась модель:

**Использовалась ли память:** нет. Поиск в начале задачи возвращал записи прошлых задач, но не по теме (задачи серии затрагивают разные области) и с низким сходством 0.24–0.29; у всех записей счётчик обращений — 0. Механизмы обучения Ruflo (эпизоды, паттерны, навыки, консолидация) остались пустыми. Автопамять Claude Code за серию тоже ничего не записала.

### 2.5. Большой проект (фаза 9, завершена)

В сервисы заложены двойники механизмов из задач (своя смена площадки с триггером `halls.forbid_venue_change`, свои шаблоны с CHECK и `debt → paid`, свои сроки 30 дней с литералом в фоновой задаче, своя дедупликация с `_same_track`, свои обязательные поля и слушатели ORM, свой лимит мест с триггером по реплике). ## 3. Промежуточные выводы

**Подтверждается:**
1. **Bootstrap работает.** Модель знаний, собранная детерминированными экстракторами + LLM по модулям, покрывает почти все правила и неочевидные связи (0.985), включая правила, живущие только в БД, событиях и BPM. Сверка источников находит реальные расхождения.
2. **Drift detection надёжен на значимых изменениях**, включая перенос логики во вспомогательную функцию — слабое место, которое мы ожидали.
3. **Дисциплина агента.** С AGENTS.md агент стабильно вызывает `find_entry`/`impact` до правок и сам обновляет модель и документацию после изменения.
4. **Документация для людей** из модели полная и точная (Doc QA 0.98).

**Большой проект (в 4–5 раз больше, с двойниками):**
- Выигрыш в полноте связей у графа есть, но узкий: +2.6 п.п. в среднем, целиком за счёт одной задачи с длинной цепочкой через процесс и события (T03: 1.0 против 0.82, устойчиво в обоих повторах).
- Экономии не подтвердилось и здесь: стоимость в сумме равна, токенов у SL на 21% больше. Граф снижает число файлов, читаемых целиком (в 2 раза), но пакет `impact` добавляется к чтению, а не заменяет его.
- Рост проекта сломал две связи в модели (конфликт имён с двойником, неоднозначный вывод литерала) — CI поймал одну, вторая прошла молча. Исполнитель SL нашёл обе связи сам.

**Не подтверждается на малом стенде:**
5. **Выигрыша в поиске скрытых связей у S по сравнению с B1 нет**: 0.83 против 0.79 на T01, 0.86 против 0.86 на T04. Тексты у вариантов одинаковые (B1 получил те же сгенерированные `docs/`), различается только способ доставки — и на проекте этого размера grep по хорошей документации работает не хуже графа.
6. **Экономии токенов нет — наоборот.** S тратит на сбор контекста на 40–70% больше токенов, чем B1: агент читает пакет `impact` (до 4000 токенов), а потом всё равно открывает файлы. Стоимость задач при этом сопоставима.

**Найденные недостатки решения:**
7. `impact` упирается в бюджет: 9 из 10 пропусков — обрезка. При этом точность пакета ~0.4–0.5: половина бюджета уходит на нерелевантные узлы. Нужна приоритизация по типу рёбер и задаче, а не только бюджет.
8. Хэш реагирует на имена локальных переменных → ложные suspect при любом рефакторинге.
9. Нет явной проверки «событие без подписчиков / подписчик без издателя», хотя данные для неё в графе есть.
10. Модель хранит номера строк → любой PR с кодом требует пересборки модели и `docs/` (шумные диффы).
11. Лог MCP неполон: подписчики в других сервисах попадают в текст ответа, но не в `nodes_returned`.

**Ruflo:**
12. По умолчанию память не формируется: мост памяти Ruflo строится на автопамяти Claude Code, а агент сам ничего не сохраняет. Память появляется только с явным протоколом в AGENTS.md (search в начале, store в конце) — и тогда она содержательная: записи фиксируют найденные ловушки.
13. В серии из 5 задач разных областей память ни разу не пригодилась: поиск возвращал нерелевантные записи, обращений — 0. Семантический поиск по умолчанию на английской модели эмбеддингов (all-MiniLM-L6-v2) — для русских записей сходство низкое.
15. Записи памяти дублируют то, что должно попадать в модель знаний (ловушки, связи). Без правила «что идёт в память, а что в правила модели» это два источника правды — как и предупреждало ревью решения.
14. Эксплуатационные риски: `init` по умолчанию пишет в глобальный `~/.claude/CLAUDE.md` и ставит плагины; `.mcp.json` ссылается на `ruflo@latest`; хуки обновляют свои скрипты из глобального кэша npx; выгрузка памяти падает с внутренней ошибкой (`policy-anchor-log-missing`). Всё обходится флагами и закреплением версии — это зафиксировано в `run_scenario.md`.

## 4. Ограничения и угрозы валидности

- **Размер проекта.** Малый (~45 тыс. токенов) и большой (~170–200 тыс.) проекты всё ещё укладываются в окно модели; на кодовых базах в миллионы токенов картина может быть другой. Большой проект — один прогон генерации, двойники заложены по спецификации.
- **Мало повторов.** 2 повтора на вариант; разброс у B1 на T01 — 0.67 / 0.92.
- **Оценщик из того же семейства моделей.** Аудитор — Claude, как и исполнитель; ручная проверка выборки его оценок ещё не сделана. Аудитор ошибочно ставит `depth_cutoff` прогонам B1 (у них нет графа) — категории причин для B1 надо исправить.
- **T01 использовался при настройке решения** (пример из раздела 8 решения) — результат S на нём может быть завышен.
- **B2 = 1.0 частично по построению** (находки слепого аудита вошли в эталон).
- **Серия SMB — один прогон на задачу и без парного S** на тех же задачах: успех серии нельзя приписать именно Ruflo, а не модели знаний.
- **Лимит подписки** прервал первый запуск пилота; 10 сбойных прогонов отделены и не входят в данные.
