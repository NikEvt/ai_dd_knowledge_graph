# Бизнес-требования

Как должна работать система — по решению бизнеса. Правят люди: аналитик, продукт. Правила в
`knowledge/rules/` описывают, как система работает сейчас (извлечены из кода), и ссылаются сюда через
`satisfies` (правило реализует требование) и `deviates_from` (правило расходится с требованием).

Формат одного требования:

```markdown
## REQ-KIND-01 Вид заявки определяется при создании
владелец: продукт · статус: утверждено · схема: §9

Свободный текст: что должно быть, без путей к коду и технических деталей.
```

- ID `REQ-<ОБЛАСТЬ>-NN` не меняется, даже если текст или нумерация разделов схемы поменялись.
- `статус`: `предложено` (черновик, ещё не утверждён), `утверждено`, `отменено`.
- `схема` — раздел исходного документа (`knowledge/sources/erp-library.md`), необязательно.
- Текст требования можно менять свободно: правила, которые его реализуют, станут `suspect`
  с причиной «требование изменилось», и разработчик (или агент) сверит реализацию.

Требования нарезаны из `knowledge/sources/erp-library.md` ИИ и имеют статус `предложено`, пока их не утвердит
владелец (PR с ревью владельца, см. `.github/CODEOWNERS`).
