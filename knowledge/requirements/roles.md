# Требования: роли, закрепление и доступ

## REQ-ROLE-01 Один сотрудник — одна роль
владелец: продукт · статус: предложено · схема: §2, §16

Совмещения ролей нет: у каждого сотрудника ровно одна роль.

## REQ-ROLE-02 В заявке действует только закреплённый за ней сотрудник
владелец: продукт · статус: предложено · схема: §3, §4

Действовать в заявке может только тот, кто за ней закреплён в своей роли; каждый этап двигает вперёд только
закреплённый за ним сотрудник. Главный бухгалтер работает с платежами по всем заявкам, но за заявками не
закрепляется.

## REQ-ROLE-03 Оператор — создатель заявки, переназначить его нельзя
владелец: продукт · статус: предложено · схема: §3

За заявкой закрепляется оператор, который её создал. Переназначить оператора нельзя: на время отсутствия
оператор передаёт свою учётную запись коллеге.

## REQ-ROLE-04 Оператор работает только со своими заявками
владелец: продукт · статус: предложено · схема: §2

Оператор не может работать с заявками, за которыми закреплён другой оператор.

## REQ-ROLE-05 Проверяющего назначает руководитель проверяющих
владелец: продукт · статус: предложено · схема: §2, §3

Проверяющего на заявку назначает и переназначает только руководитель проверяющих. Сам руководитель заявки не
проверяет. Без назначенного проверяющего заявка не может пройти проверку.

## REQ-ROLE-06 Подтверждает или возвращает заявку только назначенный проверяющий
владелец: продукт · статус: предложено · схема: §2

Проверяющий работает только с заявками, на которые его назначили: взять заявку на проверку сам он не может.
Он подтверждает заявку или возвращает её оператору на доработку.

## REQ-ROLE-07 Бухгалтер закрепляет заявку за собой сам
владелец: продукт · статус: предложено · схема: §2, §3

Бухгалтер сам берёт в работу платные заявки, прошедшие проверку, и может забрать заявку у коллеги. В каждый
момент за заявкой один бухгалтер. У социальной заявки бухгалтера нет, пока не понадобится штраф; у заявки
в долг бухгалтера нет совсем.

## REQ-ROLE-08 Проверяющий оператор определяется площадкой заявки
владелец: продукт · статус: предложено · схема: §3, §7

За заявкой закреплён проверяющий оператор её площадки. При смене площадки закрепляется проверяющий оператор
новой площадки.

## REQ-ROLE-09 Проверяющий оператор работает только со своей площадкой
владелец: продукт · статус: предложено · схема: §2, §12

Проверяющий оператор — сотрудник площадки. Он работает только с заявками и расписанием своей площадки.

## REQ-ROLE-10 Проверяющий оператор видит только заявки своей площадки
владелец: продукт · статус: предложено · схема: §16

Проверяющий оператор видит только заявки своей площадки. Остальные роли работают с заявками всех площадок.

## REQ-ROLE-11 Администратор не работает с заявками
владелец: продукт · статус: предложено · схема: §2

Администратор не создаёт и не проверяет заявки, не выставляет счета, не привязывает платежи и не выдаёт книги.
Его зона — настройки в админке.

## REQ-ROLE-12 Клиент работает только по ссылке и не видит внутреннюю информацию
владелец: продукт · статус: предложено · схема: §1, §2

Клиент в системе только записывается на визит, переносит или отменяет его по ссылке из письма. Заявку, чат,
счета и другую внутреннюю информацию он не видит.

## REQ-ROLE-13 Представитель клиента в системе не работает
владелец: продукт · статус: предложено · схема: §1, §2

Представитель ничего в системе не подтверждает, но получает письма вместе с клиентом и может записать клиента
по ссылке. Остальное общение с клиентом идёт через представителя и оператора вне системы.

## REQ-ROLE-14 История действий по заявке: кто и когда
владелец: продукт · статус: предложено · схема: §16

Все значимые действия по заявке сохраняются в истории: кто и когда. Историю удалить нельзя. Если оператор
передал свою учётную запись коллеге, история показывает действия от имени владельца учётной записи.
