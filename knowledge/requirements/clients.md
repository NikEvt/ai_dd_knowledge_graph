# Требования: клиент, проверка данных, дубли

## REQ-CLIENT-01 Клиент заводится один раз оператором
владелец: продукт · статус: предложено · схема: §1, §6

Нового клиента заводит оператор. Клиент заводится в системе один раз, его данные общие для всех его заявок.

## REQ-CLIENT-02 Данные клиента обновляет проверяющий
владелец: продукт · статус: предложено · схема: §2, §6

Обновлять данные клиента (например, при смене паспорта) может только проверяющий. Оператор после проверки
данные клиента не меняет.

## REQ-CLIENT-03 Каждая заявка проходит проверку данных клиента
владелец: продукт · статус: предложено · схема: §2, §6

Каждая новая заявка проходит проверку, даже если клиент уже проверялся: данные могли устареть. Проверяющий
убеждается, что все нужные данные о клиенте есть и они актуальны.

## REQ-CLIENT-04 Обновление данных клиента возвращает его заявки на проверку
владелец: продукт · статус: предложено · схема: §4, §6

Обновление данных клиента сразу видно во всех его заявках. Другие его заявки, которые ещё не дошли до записи,
снова уходят на проверку; заявки на этапе записи и дальше не перепроверяются.

## REQ-DEDUP-01 Из двух заявок клиента по одной сфере остаётся первая дошедшая до записи
владелец: продукт · статус: предложено · схема: §6

Если у клиента две заявки по одной сфере, остаётся та, что первой дошла до записи: платная — в момент полной
оплаты, в долг — когда прошла проверку. Социальные и платные заявки не пересекаются. Заявки по разным сферам
друг на друга не влияют.

## REQ-DEDUP-02 Дубль закрывается окончательно, его счёт аннулируется
владелец: продукт · статус: предложено · схема: §4, §6

Вторая заявка закрывается автоматически и окончательно, без ухода в архив; вернуть её нельзя. Выставленный по ней
счёт аннулируется.
